# Missions in DRAFT Implementation Plan

> Run with /implement-plan /Users/janeshorst/Dev/mutinex-interview/.work/missions-draft/plan.md in a fresh context.

**Goal:** Move the API routes into `mc_api/routers/` and the CLI commands into `mc_cli/commands/`. Then add the skill list, and the DRAFT missions with create, list, show, edit and slots, in the API and the CLI.

**Architecture:** The API follows the FastAPI "Bigger Applications" structure. `main.py` includes one `APIRouter` for each resource. `dependencies.py` holds the shared dependencies. The missions router has a router-level role check for crew. Each mission write loads the mission with a row lock and checks the owner and the DRAFT status. Then it changes the rows and commits. The CLI has one Typer module for each command group.

**Tech Stack:** Python 3.12, FastAPI 0.143, Pydantic 2, SQLAlchemy 2.1, Typer 0.27, httpx, Rich 15, pytest, Postgres 17.

**Spec:** /Users/janeshorst/Dev/mutinex-interview/.work/missions-draft/spec.md
**Verify:** verify:full = `.claude/hooks/verify.sh full`; verify:fast = `.claude/hooks/verify.sh fast`
**Contract:** Covers, Tests must prove, Files, Interfaces, Global Constraints and Checkpoint are binding. Report each change to them to the human. The implementer chooses the code.

- Routers read tenant data only through `OrgScope`. Only `routers/health.py` (`SELECT 1`) and the login route take a raw `Session`.
- A missing row and a row of another org give the same 404 body: `{"detail": "Not found"}`.
- Exact error bodies:
  - Crew on a mission route: 403 `{"role": "CREW", "rule": "Only directors and leads manage and view missions"}`.
  - Non-owner: 403 `{"role": "<ROLE>", "rule": "Directors and leads edit only their own missions"}`.

  - Unknown skill: 422 `{"detail": "Unknown skill: <skill_id>"}`.
- Check order of a mission write: crew 403 (router dependency), then 404, then non-owner 403, then 409, then 422 for the body.

- `requires_additional_director` is derived from the current role of the lead. Never store it.
- Integration tests create their own orgs and users with `make_user` (`packages/api/tests/conftest.py:68-85`). No test assumes empty tables.
